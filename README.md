# Dota mid helper

Инструменты для роста винрейта на миде. Данные берутся из Stratz API (токен в `.env`).

## Запуск сайта
```bash
cd web && npm run dev
```
Открыть http://localhost:3000

## Обновление данных (мета, матчапы, твой пул)
```bash
node scripts/refresh-data.mjs
```

## Структура
- `web/` — сайт (Next.js): драфт-помощник
- `data/` — кэш данных Stratz в JSON
- `scripts/refresh-data.mjs` — обновление `data/`
- `analysis/` — разовые скрипты и отчёты разбора статистики

## Приложение для Windows / macOS (папка `desktop/`)
Electron-оболочка вокруг того же сайта: внутри запускается автономная сборка Next на случайном локальном порту.
```bash
cd desktop && npm install
npm run build:win   # установщик и портативная версия в desktop/dist
npm run build:mac   # dmg для проверки на Маке
```
- Данные Stratz (`data/*.json`) копируются в ресурсы приложения при сборке.
- Журнал драфтов и настройки (токен Stratz, Steam ID) хранятся в папке пользователя: Windows `%APPDATA%\Dota Mid Helper`, macOS `~/Library/Application Support/Dota Mid Helper`. Задаются на странице «Настройки» внутри приложения.
- Сборка не подписана: Windows при первом запуске покажет предупреждение SmartScreen («Подробнее» → «Выполнить в любом случае»).

## Автоподхват драфта с экрана
На стадии пиков приложение несколько раз в секунду снимает окно Доты, вырезает десять слотов верхней панели
(по долям кадра, откалибровано на 16:9) и сопоставляет их с портретами героев (`desktop/assets/heroes`,
модуль `desktop/recognize.js`). Интерфейс Доты показывает в слоте не весь горизонтальный портрет, а его вырез
(около 65% ширины от 15% слева, верхние 79% высоты), поэтому шаблоны нарезаются так же: на реальных кадрах
2560x1440 сходство с правильным героем 0.8–0.96 против 0.5–0.6 при сравнении с целым портретом. Медали рангов
закрывают нижнюю треть портрета и немного снижают сходство. Оверлей FPS (NVIDIA/Steam) в правом верхнем углу
закрывает верх последнего слота диров (герой под ним набирал 0.52–0.54 и терялся): если слот не прочитался целиком,
он сравнивается по нижним рядам кропа (без верхних 5 из 18) с порогами 0.55 и отрывом 0.15; на сохранённых кадрах
так читаются Night Stalker (0.69–0.71), Lina, Slark и пустые слоты под оверлеем, ложных срабатываний нет.
Пустые слоты отсекаются двумя шаблонами пустого слота (`desktop/assets/empty-slot*.json`: голый слот и слот с
медалью ранга, который Дота показывает на стадии пиков), «плоские» кропы (фон рабочего стола, градиенты) отбрасываются
по энергии границ. Герой принимается при сходстве ≥ 0.55 с отрывом ≥ 0.08 от второго кандидата (или ≥ 0.45,
если кроп заведомо не похож на пустой слот): подсвеченный пустой слот команды, которая сейчас пикает, давал
ложного Shadow Demon на 0.48–0.50. На странице герой принимается после двух кадров подряд с тем же результатом. Своя команда и свой слот
берутся из GSI; без GSI сторона выбирается вручную.
Кадры берёт страница приложения видеопотоком экрана (`getUserMedia` с источником «экран», `desktop/preload.js`):
поток поднимается по первому запросу и гаснет через 10 секунд без запросов, из кадра в главный процесс уходит
только верхняя полоса RGBA (и уменьшенный JPEG для хранения). Раньше каждый кадр брался через
`desktopCapturer.getSources`: на Windows такие снимки не освобождались даже при принудительной сборке мусора
(до 6 ГБ за два матча), видеопоток держит один буфер. Список экранов запрашивается без миниатюр.
Экран читается только пока запущен процесс Доты (`dota2.exe`, проверка раз в 10 секунд), иначе программа
простаивает. Когда Дота присылает GSI, захват идёт только на стадиях выбора героев и планирования; без GSI
экран читается всегда, но раз в 3 секунды. Снимаются только горизонтальные мониторы, предпочтение экрану, где в прошлый раз была стадия
пиков; окна запрашиваются лишь если все экраны чёрные. После каждого кадра вызывается принудительная сборка мусора: снимки экрана Electron держит до сборки, а V8 их
размера не видит и сборку сам не запускает, без этого процесс разрастался до 5 ГБ. Функция `gc` в главном процессе
берётся через `v8.setFlagsFromString("--expose-gc")` + `vm.runInNewContext("gc")`: переключатель `--expose-gc`
через `app.commandLine` действует только на страницы, в главном процессе `global.gc` остаётся undefined.
Баны с экрана не читаются (при кастомной сетке их не видно), вводятся вручную при желании.
Пока Дота по GSI сообщает стадию выбора героев, кадры сохраняются на диск даже если панель не распознана.
Захват экрана ограничен таймаутом 10 с (в цикле страницы 15 с): на Windows `desktopCapturer` изредка не
отвечает, и без таймаута цикл чтения экрана и автозапись драфта замирали до перезапуска. Раз в минуту в журнал
пишется сводка `[loop]` (вызовы, кадры, сохранения, последнее состояние слотов).
Прототип для отладки на скриншотах: `node tools/match-draft.mjs <скриншот> [--rects ...]`.

### Самообучение портретов (персоны, арканы)
Кадры стадии пиков сохраняются на диск (`userData/pick-frames/<matchId>/`, верхняя полоса в PNG и уменьшенный
кадр в JPEG, до 16 кадров на драфт и 8 драфтов, модуль `desktop/frames.js`). Когда «История» подтягивает
результат матча из Stratz, сервер записывает состав по слотам (`userData/pick-labels.json`, порядок игроков в
панели = `playerSlot`). Приложение сверяет два последних кадра драфта с разметкой: если базовые портреты узнали
хотя бы 5 слотов правильно (значит порядок совпал), кропы неузнанных или неверно узнанных слотов запоминаются
как дополнительные портреты героя (`userData/learned-templates.json`, до 6 на героя). Так программа выучивает
персоны и арканы, которых нет на CDN, и портрет собственного слота. Результаты матчей сервер подтягивает из
Stratz сам (`web/src/lib/sync.ts`: раз в 5 минут, для записей старше 8 минут, не чаще раза в 15 минут на запись),
а приложение доучивается при старте и каждые 5 минут, если разметка обновилась. Проверено офлайн на двух
реальных драфтах: выучены Vengeful Spirit и Night Stalker на экране планирования и Rubick в своём слоте.
Один матч в истории — одна запись: автозапись и ручное «взять» в том же матче сливаются (состав берётся
более полный).

## Диагностика
Настройки → «Сохранить диагностику»: zip в «Загрузках» с версией и системой, логами главного процесса
(текущий и прошлый запуск: `userData/main-log.txt` пишется раз в 30 с и при выходе, при старте переименовывается
в `main-log-prev.txt`), сырыми данными GSI с хронологией стадий (`phases`, переживает перезапуск), конфигом, журналом драфтов, снимком экрана с результатом распознавания и кадрами
со стадии пиков двух последних драфтов (с диска, переживают перезапуск), разметкой и сводкой выученных
портретов. Токены в файл не попадают.

## GSI (связь с Дотой)
В программе: Настройки → «Установить конфиг в Доту». Кладёт файл `gamestate_integration_midhelper.cfg` в
`dota 2 beta\game\dota\cfg\gamestate_integration\`. Программа слушает порт 3781.
Проверено на реальных данных: обычному игроку Дота отдаёт только его выбранного героя и номер матча,
блок `draft` пустой (состав драфта доступен только зрителям). Поэтому в режиме «Авто» врагов вводишь сам,
а программа дописывает твоего героя и номер матча и сама сохраняет драфт в историю после выбора героя.

## Роли
Переключатель роли в шапке пикера: пул, базовые винрейты, порог «играется на этой роли» и вес матчапов
по лейну (для мида 1v1, для остальных ролей оппоненты по лейну) берутся для выбранной роли. Пул редактируется
отдельно для каждой роли, правки хранятся в браузере программы.

## Обновления программы
Репозиторий закрытый, поэтому для проверки обновлений в Настройках нужен токен GitHub
(Fine-grained token с правом Contents: Read на этот репозиторий). Новая версия: поднять `version`
в `desktop/package.json`, закоммитить, `git tag vX.Y.Z && git push origin main --tags`;
GitHub Actions соберёт установщики и опубликует релиз.
